# Upgrading to v2.16.0

The service no longer reads `POSTGRES_DSN`. It reaches PostgreSQL only through the discrete settings, so no credential-bearing URL is configured anywhere.

## Do I need to act?

**Required** if a deployment of the `rest`, `jobs/migrations`, `jobs/maintenance` or `standalone-rest` image sets `POSTGRES_DSN` without `POSTGRES_HOST`. A deployment that sets `POSTGRES_HOST` has ignored `POSTGRES_DSN` since v2.5.3: take this release as-is and delete the unused variable.

## Replace POSTGRES_DSN with the discrete settings

Split the URL `postgres://<user>:<password>@<host>:<port>/<database>?sslmode=<mode>` into one variable per part:

| URL part                     | Variable                                                    |
| ---------------------------- | ----------------------------------------------------------- |
| `<host>`                     | `POSTGRES_HOST`                                             |
| `<port>`                     | `POSTGRES_PORT`, which defaults to `5432`                   |
| `<user>`                     | `POSTGRES_USER`                                             |
| `<password>`                 | `POSTGRES_PASSWORD`, injected as a secret                   |
| `<database>`                 | `POSTGRES_DATABASE`                                         |
| `sslmode=disable`            | `POSTGRES_TLS_ENABLED=false`                                |
| any other `sslmode`, or none | leave `POSTGRES_TLS_ENABLED` unset, which encrypts the link |

```sh
# before
POSTGRES_DSN=postgres://agora:p%40ss@db.internal:5432/agora?sslmode=disable

# after
POSTGRES_HOST=db.internal
POSTGRES_PORT=5432
POSTGRES_USER=agora
POSTGRES_PASSWORD=p@ss
POSTGRES_DATABASE=agora
POSTGRES_TLS_ENABLED=false
```

`POSTGRES_PASSWORD` holds the raw password: decode any percent-escape the URL carried, such as `%40` for `@`.

With TLS enabled, the service checks the server certificate against the system roots and the name in `POSTGRES_HOST`, as `sslmode=verify-full` did. Every other `sslmode` checked less, and no setting replaces `sslrootcert`: the server must present a certificate the image already trusts. Disable TLS only when another trusted boundary protects the database link.

Without `POSTGRES_HOST`, the first database connection fails with `pgdriver: invalid scheme`. With `POSTGRES_HOST` but no `POSTGRES_PASSWORD`, the process stops at startup with `postgres password is empty`. Once the new configuration is deployed and healthy, delete `POSTGRES_DSN` and any secret that held it.
